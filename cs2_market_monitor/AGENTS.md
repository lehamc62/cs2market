# CS2 Market Monitor — инструкции для Codex

## Цель
Разработать локальный Python-проект для мониторинга рынка предметов Counter-Strike 2 на основе CSFloat: история **завершённых продаж**, текущие **объявления**, визуализация, отслеживание аномалий, позднее Telegram-уведомления и исследовательские вероятностные модели. Первый отслеживаемый предмет — **★ Skeleton Knife | Doppler (Factory New), Phase 4**.

## Перед каждой задачей
1. Прочитай `docs/PROJECT_CONTEXT.md` и относящиеся к задаче пункты `docs/ROADMAP.md`.
2. Проверь фактически существующие Python-файлы в проекте. Пользователь переносит рабочие файлы отдельно; не считай, что они уже существуют, пока не увидел их.
3. Отличай **проверено пользователем** от **планируется**. Не изобретай эндпоинты, схему JSON, поля или текущие рыночные цены.
4. Работай маленькими проверяемыми шагами. Перед изменениями кратко объясни план; после — покажи, какие файлы изменены и как проверить.

## Известная рабочая конфигурация
- ОС: Windows; пользователь работает с PyCharm и Python 3.14.
- HTTPS: на этом окружении была ошибка `SSLCertVerificationError`; с `truststore.inject_into_ssl()` запросы стали выполняться. Не использовать `verify=False`.
- Авторизация CSFloat: `Authorization: <значение CSFLOAT_API_KEY>` (без Bearer), ключ хранится в переменной окружения `CSFLOAT_API_KEY`, а не в коде.
- Рабочий `GET https://csfloat.com/api/v1/listings` с `paint_index=421`, `market_hash_name=★ Skeleton Knife | Doppler (Factory New)`, `category=1`, `sort_by=lowest_price`, `type=buy_now`; 2026-11-17 получено HTTP 200 и 20 объявлений.
- Рабочий `GET https://csfloat.com/api/v1/history/{URL-encoded market_hash_name}/graph` с `paint_index=421`; 2026-11-17 получено 28 дней завершённых продаж (2026-10-20…2026-11-16) и CSV.
- Денежные значения API — в центах USD; отображаемые цены = значение / 100.

## Принципы аналитики
- **Не смешивай объявления с завершёнными продажами**. Отдельно храни `lowest_listing_price`, `daily_sales_avg_price`, `sales_count`.
- `paint_index=421` означает Phase 4; не смешивать с другими фазами Doppler. Проверять дополнительные характеристики (float/pattern/редкие вариации) перед сравнениями.
- Не трактуй «среднюю цену за день» как цену каждого предмета; отслеживай размер выборки.
- Прогнозы являются вероятностными гипотезами: используй бэктест с временным разбиением, baseline, ошибку прогноза, интервал неопределённости и комиссии. Не обещай гарантированную прибыль и не совершай сделки автоматически.
- Пока проект **строго read-only** относительно торговой площадки: только GET, без покупки, выставления/снятия объявлений или торговли.

## Код и безопасность
- Используй простой, поддерживаемый Python, типизацию там, где это полезно; не добавляй тяжёлые зависимости без необходимости.
- Не переписывай рабочий код без причины. Сначала прочитай его и предложи минимальные изменения.
- HTTP: timeout, `raise_for_status`, диагностические сообщения без секретов, разумное соблюдение rate limits, без обхода блокировок сайта.
- Никаких секретов в исходниках, логах, тестах, git, README и ответах. `.env`, если будет создан, должен быть исключён из Git.
- Не делай сетевых запросов в тестах по умолчанию; используй фикстуры из `data/fixtures` и моки.
- Отделяй загрузку данных от расчётов и визуализации, чтобы можно было работать офлайн с CSV.
- Пользователю отвечай **по-русски**, пошагово, с небольшими понятными примерами; SQL при необходимости — хорошо отформатированный многострочный.
